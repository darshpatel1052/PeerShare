## Why these changes fit the product

Studio needs server-side pagination because published videos and old upload attempts share one management collection. Filtering a small client-side window cannot answer “show all my published videos.” The API now returns items, an opaque next cursor, matching result count, and publication totals. A database index begins with owner ID and follows the same creation-time/UUID ordering as the page query.

Processing events describe coordinator state, while commands describe newer creator intent. Their version numbers answer different questions. Matching command IDs and updating the command and read model in one PostgreSQL transaction prevents an older response from consuming a newer action. The coordinator remains responsible for deciding whether work completed or stopped.

A React request cache also has an ownership boundary: URL alone is insufficient for a private playlist. Adding account identity to the resource scope clears the visible result synchronously during render, aborts the older request and reloads under the new session. The video player can continue because public playback has separate authorization.

Storage allowance should become available when abandoned objects are actually gone. The sweeper now tracks completion of both paginated bucket walks and retries unsuccessful pages. Its conservative settlement cutoff covers the maximum lifetime of a stopped worker, so a late write is still covered by the earlier reservation.
